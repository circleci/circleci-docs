= How to use the Chunk CLI
:page-platform: Cloud
:page-description: How to use the `chunk` CLI to generate AI review prompts, validate changes in Chunk sidecars, trigger tasks, and configure validation hooks.
:experimental:

This page covers the main `chunk` CLI workflows. For installation, authentication, and first-time setup, see xref:install-and-configure-the-chunk-cli.adoc[Install and Configure the Chunk CLI].

[#typical-workflow]
== Typical workflow

Once set up, your day-to-day workflow looks like this:

. Make your changes.
. Ask your agent to review: type `/chunk-review`, or say "review my changes" or "review PR #123".
. Ask your agent to validate remotely: type `/chunk-sidecar`, or say "validate on the sidecar".
. Push when checks pass.

[#run-validation-in-a-sidecar]
[badge="Preview"]
== Validate in a Chunk sidecar

CAUTION: Chunk sidecars are available in preview on all CircleCI plans. The product is in active development and you may encounter bugs, unexpected behavior, or incomplete features. If you have feedback, you can share it on our link:https://discord.com/invite/circleci[Discord]. When the feature becomes generally available, a cost applies for access and usage.

Chunk sidecars run your quality checks in a CircleCI Cloud environment that matches your CI pipeline, catching failures that do not reproduce locally.

The easiest way to get started is to ask your AI agent. For first-time setup, say "set up chunk sidecar" or type `/chunk-sidecar-setup`. For ongoing validation, say "validate on the sidecar" or type `/chunk-sidecar`. The skills handle auth, sidecar creation, file sync, and validation automatically.

To set up from the CLI instead, run:

[source,console]
----
$ chunk sidecar setup --name <name>
----

This detects your tech stack, syncs your files, runs install steps, and creates a snapshot — all in one step. After the first run, the detected environment is saved to `.chunk/config.json` and reused automatically. Pass `--force` to re-detect.

TIP: Use `chunk watch` for a live dashboard of sidecar status and recent activity. Pass `--focus` to limit it to the current directory.

=== Sidecar command reference

[.table-scroll]
--
[cols=2*, options="header"]
|===
|Task |Command

|Create a sidecar
|`chunk sidecar create --name <name>`

|Create from a snapshot
|`chunk sidecar create --name <name> --image <snapshot-id>`

|Set the active sidecar
|`chunk sidecar use <sidecar-id>`

|Sync local files to the active sidecar
|`chunk sidecar sync`

|SSH into the active sidecar
|`chunk sidecar ssh`

|Create a snapshot
|`chunk sidecar snapshot create --name <snapshot-name>`

|List snapshots
|`chunk sidecar snapshot list`

|List all sidecars
|`chunk sidecar list`
|===
--

CAUTION: `chunk sidecar snapshot create` deletes the source sidecar once the snapshot is captured. Launch a new sidecar from the snapshot with `chunk sidecar create --image <snapshot-id>` to resume work.

[#run-validation]
== Validate your changes locally

The `chunk validate` command runs the commands configured in your project's `.chunk/config.json`.

[source,console]
----
$ chunk validate              # run all commands
$ chunk validate test         # run a specific named command
$ chunk validate --remote     # run on the active sidecar (recommended for CI parity)
$ chunk validate --cmd "go test ./..."  # run an inline command
----

[.table-scroll]
--
[cols=2*, options="header"]
|===
|Flag |Description

|`--list`
|List all configured commands and their status.

|`--dry-run`
|Show the commands that would run, without executing them.

|`--cmd <command>`
|Run an inline command instead of configured commands. Add `--save` to persist it to config.

|`--remote`
|Run on the active sidecar. Creates one if none exists.

|`--local`
|Force all commands to run locally, even those configured as remote.
|===
--

For additional flags (`--env-file`, `--sidecar-id`, `--async`, and others), see the link:https://github.com/CircleCI-Public/chunk-cli/blob/main/docs/CLI.md[Chunk CLI reference, window=_blank].

[#trigger-chunk-tasks]
== Trigger Chunk tasks

The `chunk task` command triggers a xref:guides:toolkit:chunk-setup-and-overview.adoc[Chunk Task] in CircleCI Cloud from your terminal.

Before triggering a task for the first time, run `chunk task config` from your project directory to set up `.chunk/run.json`. The command prompts you to select a CircleCI project and saves the selection.

Then trigger a task run:

[source,console]
----
$ chunk task run --definition <name-or-uuid> --prompt "<prompt text>"
----

[.table-scroll]
--
[cols=2*, options="header"]
|===
|Flag |Description

|`--definition <name-or-uuid>`
|Required. Name or UUID of the Chunk task definition to run.

|`--prompt <text>`
|Required. Prompt text to send to the task.

|`--branch <branch>`
|Override the branch the task checks out.

|`--new-branch`
|Create a new branch for the task run.
|===
--

[#configure-hooks]
== Validation hooks

`chunk init` adds three hooks to `.claude/settings.json`:

* **PreToolUse**: runs before every `git commit` and blocks it if validation fails.
* **Stop**: runs when your agent session ends and validates any uncommitted changes.
* **UserPromptSubmit**: delivers results from background validation runs at the start of the next turn.

To reinstall hooks without re-running initialization, run `chunk init --skip-validate`.

=== Disable and re-enable hooks

To temporarily skip Stop-hook validation without editing `.claude/settings.json`:

[source,console]
----
$ chunk hook disable    # skip hooks until re-enabled
$ chunk hook enable     # re-enable hooks
$ chunk hook status     # show current state
----

=== Background validation

When the `chunk watch` daemon is running, the Stop hook can hand off small or low-risk changes to validate in the background, letting the agent continue working. Results arrive on the next turn. Large changes and failures always block.

To configure this behavior, say "configure background validation" to invoke the `chunk-validate-config` skill, or set the keys directly:

[source,console]
----
$ chunk config set asyncValidate auto     # default: release small changes
$ chunk config set asyncValidate never    # always block
$ chunk config set asyncValidate always   # always release
----

[#generate-a-review-prompt]
== Generate a team review prompt

`chunk build-prompt` mines your GitHub PR review history and uses Claude to produce `.chunk/context/review-prompt.md` — a file that encodes your team's review standards. The `chunk-review` skill picks it up automatically.

[NOTE]
====
`chunk build-prompt` requires GitHub and Anthropic credentials. See xref:install-and-configure-the-chunk-cli.adoc#authentication[Authentication] in the install guide.
====

[source,console]
----
$ chunk build-prompt
----

By default the command targets the GitHub org from your git remote, analyzes the top five reviewers, and looks back three months. Common overrides:

[.table-scroll]
--
[cols=2*, options="header"]
|===
|Flag |Description

|`--org <org>`
|Override the auto-detected GitHub organization.

|`--repos <list>`
|Comma-separated repository names to analyze.

|`--top <n>`
|Number of top reviewers to include. Default is five.

|`--since <YYYY-MM-DD>`
|Start date for the analysis window. Default is three months ago.
|===
--

Pass `--debug` to write intermediate files alongside the prompt for troubleshooting. For the full flag list, see the link:https://github.com/CircleCI-Public/chunk-cli/blob/main/docs/CLI.md[Chunk CLI reference, window=_blank].

Once `.chunk/context/review-prompt.md` exists, ask your agent to "review my changes" or "review PR #123" to start a review.
