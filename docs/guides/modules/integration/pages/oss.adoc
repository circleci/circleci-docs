[#security]
== Security

While open source can be a liberating practice, take care not to liberate sensitive information.

* If your repository is public, your CircleCI project and its build logs are also public. Pay attention to the information you choose to print.
* Environment variables set in the CircleCI application are hidden from the public. These variables will not be shared in <<pass-secrets-to-builds-from-forked-pull-requests,forked PRs>>
unless explicitly enabled.

[#features-and-settings-for-open-source-projects]
== Features and settings for open source projects

The following features and settings can be useful for open source projects.

[#private-environment-variables]
=== Private environment variables

Many projects require API tokens, SSH keys, or passwords. Private environment variables allow you to safely store secrets, even if your project is public.

For more information, see the xref:security:set-environment-variable.adoc#set-an-environment-variable-in-a-project[Set an Environment Variable] document.

[#only-build-pull-requests]
=== Only build pull requests

Open source projects have significantly more commits than private projects, so building every commit from every branch might be excessive and costly (both in terms of time and credits usage).

You can modify this behaviour by restricting builds to branches that have pull requests. For steps, see the xref:pull-request-build-settings.adoc#only-build-pull-requests[Pull Request Build Settings] page.

[#build-pull-requests-from-forked-repositories]
=== Build pull requests from forked repositories

Many open source projects accept PRs from forked repositories. Building these PRs is an effective way to catch bugs before manually reviewing changes. For steps, see xref:pull-request-build-settings.adoc#build-pull-requests-from-forked-repositories[Build Pull Requests From Forked Repositories].

[#pass-secrets-to-builds-from-forked-pull-requests]
=== Pass secrets to builds from forked pull requests

Running an unrestricted build in a parent repository can be dangerous. Projects often contain sensitive information, and this information is freely available to anyone who can push code that triggers a build. For what CircleCI hides by default and how to turn this setting on, see xref:pull-request-build-settings.adoc#pass-secrets-to-builds-from-forked-pull-requests[Pass Secrets to Builds From Forked Pull Requests].

[#caching]
=== Caching

For how caches work in builds from forked pull requests, see xref:pull-request-build-settings.adoc#caching-for-forked-pull-requests[Caching in Forked Pull Request Builds].
