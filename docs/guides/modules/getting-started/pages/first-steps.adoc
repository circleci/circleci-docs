= Sign up and try CircleCI
:page-platform: Cloud
:page-description: First step for using CircleCI.
:experimental:

To start building on CircleCI, sign up for an account, then create an organization for your team, or join teammates who are already using CircleCI. CircleCI supports GitHub, Bitbucket, and GitLab projects.

Choose how to sign up:

* New to CircleCI and signing up in a browser? See <<sign-up-in-the-web-app>>.
* Prefer to stay in the terminal, or signing up as part of a script or agent workflow? See <<sign-up-with-the-cli>>.
* Joining a team that already uses CircleCI? See <<join-an-existing-org>>.

TIP: Your sign-in method determines which kind of organization you get. If that sounds unfamiliar, see <<understand-org-types-and-sign-in-methods>> after you sign up.

[#sign-up-in-the-web-app]
== Sign up in the web app

From the link:https://circleci.com/signup/[Sign Up] page, do one of the following.

[#github-gitlab-bitbucket-data-center]
=== Sign up to build GitHub, GitLab, or Bitbucket Data Center projects

If you want to build mainly **GitHub**, **GitLab**, or **Bitbucket Data Center** projects, sign up with your email address to create an account.

TIP: If you want to collaborate on an existing org you can create an account and request an invite later.

. Select btn:[Sign Up].
. Enter your email address and create a password.
. Verify your email address.
. Set up MFA by following the instructions in the web app.
. Choose one of the following:
** Use the <<join-an-existing-org,Find Your Team>> option to connect your account to a shared org.
** Follow the steps in <<sign-up-and-create-an-org>>.

=== Sign up to build Bitbucket Cloud projects

If you want to primarily build **Bitbucket Cloud** projects, sign up with your Bitbucket account. Your org in CircleCI maps directly to your Bitbucket workspace.

. Select btn:[Sign Up With Bitbucket].
. Log in to your Bitbucket Cloud account.
. Once logged in and authorized, you will be taken to the CircleCI web app. At this point you have one `bitbucket` organization created for you with the name of your Bitbucket workspace.
. You can now select *Projects* from the left sidebar and follow your projects. For Bitbuckets cloud one repository equals one project. When you follow a project you will see the project's pipelines and runs in the web app.

[#sign-up-with-the-cli]
== Sign up with the CLI

//  Living section: CircleCI is actively building a more agent-first CLI onboarding
//  experience. As of this writing, `circleci onboard` and `circleci auth signup` both
//  hand off to the same browser-based signup flow described in <<sign-up-in-the-web-app>>
//  rather than completing signup natively in the terminal. Re-check this section against
//  `circleci onboard --help` and `circleci auth signup --help` whenever the CLI changes,
//  and update or remove the NOTE below once signup no longer requires a browser.
[NOTE]
====
The CLI's onboarding flow is evolving toward a fully terminal-native experience. Currently, starting signup from the CLI opens a browser and hands you off to the same flow described in <<sign-up-in-the-web-app>>.
====

The link:https://cli.circleci.com/[CircleCI CLI] has two commands that start signup:

[,shell]
----
circleci onboard      # scans your repository, generates a config, and signs you up
circleci auth signup  # signup only, no project setup
----

Both commands open a browser to complete the actual signup, using the same account types and VCS providers described in <<sign-up-in-the-web-app>>. Add `--no-browser` to either command to print the sign-in URL instead of opening a browser, for example if you are running the command on a remote or headless machine.

Because signup currently requires a browser step no matter which CLI command you use, you cannot complete signup end to end today. Do one of the following:

* Print the URL with `--no-browser` and ask a human to open it once to complete sign-in.
* Skip interactive authentication entirely by setting the `CIRCLE_TOKEN` environment variable to a token your organization has already provisioned for you. This works for any `circleci` command, including `project create` and `onboard`, without a browser step.

[#join-an-existing-org]
== Join an existing org

If your team already uses CircleCI, join their organization instead of creating a new one. Use whichever of the following matches what you have.

=== Join using an invite link

If you have an invite email from your team, you will be _joining_ an existing CircleCI organization, whether or not you already have a CircleCI account.

. Follow the link in your invite email and follow the instructions in the web app.
. You will be taken to your organization's dashboard in the CircleCI web app. From here, you can follow projects or trigger pipelines in projects to which you have access in your organization, or xref:create-project.adoc[Create New Projects].

NOTE: If you are setting up a project for the first time, you may need to authenticate with your VCS provider. Once you have completed a one-time authentication, you will be able to set up subsequent projects in CircleCI more quickly. Refer to the xref:create-project.adoc[Creating a Project] guide for more information.

=== Join without an invite

If you do not have an invite link, you can search for your team instead.

. After creating an account, select **Find Your Team** in the **Join Your Teammates** card on your link:https://app.circleci.com/home/[homepage]. This option is also available at any time from the **Join Organization** menu.
+
.Welcome screen with the find your team menu expanded
image::guides:ROOT:getting-started/find-your-team.png[Screenshot showing the welcome screen with the find your team menu expanded]
. Choose one of the following:
** *Search via GitHub*: authorize the GitHub OAuth app for read access to your GitHub organization membership. CircleCI then lists all matching organizations you are eligible to join — select btn:[Join Organizations] to complete joining.
** *Search via Bitbucket Cloud*: enter your Bitbucket Cloud credentials to authorize CircleCI. You are added to your organization automatically.

NOTE: If you do not see the organization you want to join listed, ask your organization admin for an invite instead. For the steps admins use to send invites, see the xref:invite-your-team.adoc[Invite Your Team] page.

For a guide to integrating your code with CircleCI, see the xref:permissions-authentication:users-organizations-and-integrations-guide.adoc[Users, Organizations, and Integrations Guide].

[#understand-org-types-and-sign-in-methods]
== Understand org types and sign-in methods

Your sign-in method and VCS provider together determine what kind of CircleCI organization you get:

* If you sign up with **email and password** and set up **GitHub**, **GitLab**, or **Bitbucket Data Center** as an add-on for your org, you set the version control system (VCS) integration type when you create your org, and authenticate with your VCS provider as part of that setup. Team members that you invite to your org can join without authenticating with your VCS, but if they create new projects, they authenticate at that point instead.
* If you sign up or sign in with a **GitHub** social login, CircleCI creates a matching organization for you automatically.
* If you sign up or sign in with **Bitbucket Cloud**, CircleCI creates a matching organization for you automatically, and every team member joining your org authenticates with Bitbucket _during_ signup, not later.

You cannot use these sign-in methods interchangeably for the same account. For example, if you have an email and password account and then use a social login, CircleCI creates a separate, new account connected to your VCS provider.

For the full picture of organization types and VCS integrations and how they affect project creation, see the xref:permissions-authentication:users-organizations-and-integrations-guide.adoc[Users, Organizations, and Integrations Guide].
