= Migrate from the tests commands to Smarter Testing
:page-platform: Cloud
:page-vcs: all
:page-plan: Free, Performance, Scale
:page-audience: developer
:experimental:
:page-description: Move test jobs that use the circleci tests glob, split, and run commands to circleci testsuite, with CircleCI agent skills or by hand.

If your test jobs use the `circleci tests glob`, `circleci tests split`, or `circleci tests run` commands, you can move them to `circleci testsuite` to use Smarter Testing. Your existing commands continue to work, so you can migrate one job at a time.

After you migrate, static test splitting and rerunning only failed tests work with no extra configuration. You can then enable the Smarter Testing capabilities that have a credit charge. See the xref:smarter-testing-overview.adoc[Smarter Testing Overview].

[#migrate-with-agent-skills]
== Migrate with agent skills

The `circleci-testsuite` agent skill migrates an existing test step to `circleci testsuite`. It writes your `.circleci/test-suites.yml` file, replaces your test command, and runs `circleci testsuite doctor` to check the result.

. Install the xref:toolkit:circleci-agent-skills.adoc#install-circleci-agent-skills[CircleCI Agent Skills] in your AI coding agent.
. In your project, ask your agent to migrate your tests, for example: `Migrate my test job to CircleCI Smarter Testing.`
. Review the changes to `.circleci/config.yml` and `.circleci/test-suites.yml`, then push them to a feature branch.
. Verify the test job, as described in xref:getting-started-with-smarter-testing.adoc#verify-in-ci[Getting Started With Smarter Testing].

To enable test impact analysis, dynamic test splitting, or auto rerun failed tests afterwards, ask your agent to set up Smarter Testing. The `circleci-smarter-testing` skill asks you which capabilities to enable.

[#migrate-by-hand]
== Migrate by hand

To migrate by hand, follow xref:getting-started-with-smarter-testing.adoc[Getting Started With Smarter Testing], using your existing `circleci tests` setup as the starting point. The following table shows where each part of that setup goes:

[.table-scroll]
--
[cols="1,2", options="header"]
|===
| Before: `circleci tests` | After: `circleci testsuite`

| `circleci tests glob` lists your test files.
| The `discover` command in `.circleci/test-suites.yml` lists your test atoms.

| `circleci tests run --command="..."` or `circleci tests split` passes the test files to your test runner.
| The `run` command in `.circleci/test-suites.yml` runs your test runner, with the `<< test.atoms >>` placeholder in place of the file list.

| `--split-by=timings` splits by timing data.
| Static test splitting is built in. Set `parallelism` on the job and `circleci testsuite run` splits by timing data from previous runs.

| *Rerun failed tests* in the web app reruns only failed tests.
| Select *Rerun workflow from failed*. `circleci testsuite run` reruns only the failed tests.

| The `store_test_results` path matches where your test runner writes JUnit XML.
| The `store_test_results` path must match the directory of `outputs.junit` in `.circleci/test-suites.yml`.
|===
--
