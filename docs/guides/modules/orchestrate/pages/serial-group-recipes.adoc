These recipes show how to use serial groups to run jobs one at a time. For how serial groups work, the queueing rules, and how to release a group from the web app, see xref:controlling-serial-execution-across-your-organization.adoc[Controlling Serial Execution Across Your Organization].

Each example is a complete configuration file that you can adapt. Replace the `./scripts/` commands with your own.

. Trigger a run in two of the projects at the same time. The second deploy job shows a _queued_ status until the first deploy job finishes.

=== Notes

* A serial group applies across your organization. Two jobs in different projects are in the same group when their `serial-group` values are identical.
* Do not add `<< pipeline.project.slug >>` to the value. It gives each project its own group, so deployments from different projects no longer queue behind each other. To serialize within one project only, see <<run-one-deployment-at-a-time-for-each-project,Run one deployment at a time for each project>>.
* The next job in the queue starts when a job finishes, whatever the job's final status.
* A job that requires the deploy job runs only if the deploy job succeeded. Releasing the lock does not change this.
* A job waits in the queue for up to five hours. After that, CircleCI cancels it.
* If a newer pipeline in the same project is waiting or running in the group, a job from an older pipeline is skipped. To roll back to an earlier version, rerun a workflow from the earlier pipeline when no job in the group is waiting or running.

----

=== Notes

* The lock is released as soon as the `migrate` job finishes. The `deploy` job in this example is not part of the group, so another service can start its migration while this service deploys.
* If a migration fails, CircleCI still releases the lock and the next migration in the queue starts. The `deploy` job does not run, because it requires `migrate` to succeed.
* A newer pipeline in the same project takes priority over an older one. An older pipeline's migration job is skipped when a newer pipeline's job is waiting or running in the group.
