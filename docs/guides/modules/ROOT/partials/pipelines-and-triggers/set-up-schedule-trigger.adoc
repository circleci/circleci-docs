GitHub App, GitHub App Server, and Cursor Origin::
+
--
include::ROOT:partial$app-navigation/steps-to-project-settings.adoc[]

. Select **Project Setup** in the sidebar.
. Locate your pipeline and select btn:[Schedule +].
. Complete the schedule trigger form:
+
.Screenshot showing the schedule trigger form
image::guides:ROOT:triggers/set-up-schedule-trigger.png[Schedule triggers web app form]
** Give your trigger a descriptive name.
** Enter a **Config branch**. CircleCI fetches your config file from this branch.
** Enter a **Checkout branch**. CircleCI checks out your code from this branch.
** Under **Pipeline attribution**, select the actor to initiate the trigger. You can choose yourself, or the scheduling system if you want the trigger to be independent from individual users. If your project requires the use of environment variables stored in restricted contexts, you must assign someone who has access to those contexts.
** Optionally, select btn:[Add parameter] to enter pipeline parameters to set when triggering the pipeline. If you enter any new pipeline parameters make sure to also add them to your config file. You can select btn:[Populate from config] to automatically populate the parameters fields from your config file.
** Enter a **Schedule (cron expression)**. Schedules must run at least 5 minutes apart. The start time can be offset by up to 10 minutes, but stays consistent across all runs.
. Make sure **Trigger status** is enabled, then select btn:[Save].

GitHub OAuth and Bitbucket Cloud::
+
--
include::ROOT:partial$app-navigation/steps-to-project-settings.adoc[]

. Select **Triggers** in the sidebar.
. Select btn:[Add Trigger].
+
.Screenshot showing the schedule trigger form
image::guides:ROOT:pipelines-scheduled-trigger-form.png[Schedule triggers web app form]
** Give your trigger a descriptive name.
** Enter an optional trigger description.
** Select the pipeline to run.
** Select a release frequency (weekly/monthly, which days/months/time etc.).
** Enter a branch or tag name to determine when to trigger the pipeline.
** Optionally, enter pipeline parameters. If you declare pipeline parameters in the form, you need to make sure they are configured in your project's `.circleci/config.yml`. See the xref:guides:orchestrate:pipeline-variables.adoc#pipeline-parameters-in-configuration[Pipeline Values and Parameters] page for more information.
** Select an actor to initiate the trigger.
. Define the new schedule by filling out the form, then select **Save Trigger**.
